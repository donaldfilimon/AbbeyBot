# Quasar completion: desktop, headless service, and live HTTPS deployment

Approved implementation specification, 2026-09-06.

Complete create → review → approve → prepare dependencies → preview → edit → rollback → archive → restore through local and authenticated remote clients. Preserve two-stage Discord proposal/content approval, bounded source access, exact-plan approval, single-writer storage, owned process groups, and compatibility with existing workspaces and receipts.

1. Extract an observable desktop workspace model. Separate create/edit, render complete bounded before/after content, cancel polling and discard stale responses on selection changes, preserve loaded data on connection errors, recover history on reopening. Bind approvals to site/generation/writes/preimages and expiry. Persist versioned mutation/rollback outcomes and recovery problems; reconcile interrupted operations on restart. Discover verified archives and exclude reproducible node_modules/.next; restores require dependency preparation.
2. Introduce QuasarWorkspaceClient local and HTTP adapters for every desktop operation. Separate backend settings from sync and put tokens in Keychain. Select once at startup; remote mode acquires no local registry. HTTPS with exact-loopback HTTP exception, reject cross-origin redirects, redact transport failures, never replay uncertain mutations. Capabilities identify stable service identity and Discord support. Owning server retains proposal payloads and freshly revalidates permissions, operator/guild policy, quiet mode, expiry and budget. Approval carries identifier/digest only.
3. Explicit bounded bun install --frozen-lockfile --ignore-scripts against reviewed manifest/lock fingerprint. Launch installed Next entry point. Allowlist child environment and local temp/cache directories. One active preview. Private preview ports; Caddy checks site/current generation, never client upstream. Dedicated desktop web view exchanges single-use 60-second tickets for host-only Secure HttpOnly 15-minute cookies, bound to site/generation. Strip operator/internal headers and auth cookies before generated code; no operator routes on preview origins. This is approved-code process supervision, not a hostile-code sandbox.
4. Package Bun, Swift runtime dependencies, all server resource bundles. Production Compose persists Quasar/Postgres, keeps ports private, bounds logs and adds health/restart policy. Linux CI builds commit-tagged private GHCR images off-host; deployment pins digest. Extend existing compatible provider with model/bearer configuration preserving defaults/router. Caddy Cloudflare DNS module holds its own scoped token. Verify domain delegation then add only required records. Maintenance rollout drains work/previews, takes consistent backup, replaces image, verifies health, and retains previous image/data.

Authenticated additions: GET /api/quasar/capabilities; GET /api/quasar/proposals; POST /api/quasar/proposals/:id/approve and /reject; GET /api/sites/:id/plan/review; GET /api/sites/:id/history; GET /api/sites/archives; POST /api/sites/:id/prepare-preview; POST /api/sites/:id/preview-session. Internal ticket redemption/Caddy authorization are unavailable on operator origin. Keep planDigest opaque and DTO changes additive.

Deployment: provider-neutral x86-64 Linux host with Docker Engine and Compose, initially one preview. The currently selected Hostinger VPS is tracked as a runtime prerequisite rather than assumed ready. API https://api.xfoss.dev; private previews https://<site-id>.preview.xfoss.dev; full Abbey server plus Postgres/Quasar persistent volumes; external inference. Verify Cloudflare zone delegation before rollout. Secure host/provider/Discord account configuration and independent backups are required; no credentials in source or chat. Public site publishing, multi-tenancy, native media and Rust Abbey are excluded.

Verification: focused desktop stale response/reconnection/restart tests; approval preimage/expiry/duplicate/interruption/rollback/archive integrity; dedicated auth/transport/capabilities/fresh Discord denial/uncertain outcomes; disabled scripts/credential filtering/one preview/HTTP+WS/process retirement; actual Linux release image resources/install/render/restart on same volumes. Then verify-all.sh with disposable databases and dry-run credentials. Ship review PR into main. Record local gates, image digest, hosted CI, HTTPS, real model desktop lifecycle, operator-submitted Discord proposals/revocation denial, and restore evidence separately. Unavailable prerequisites remain explicit and are never claimed passed.
